# 验证模块内部

面向框架开发者。本目录记录测试启动、回归范围、发布检查与手动验收；编译通过不等于运行场景通过。

## 职责与边界

- 负责：测试环境、回归范围、发布检查、手动验收清单。
- 不负责：自动化替代游戏内行为；运行测试与验收由开发者手动执行。
- 编译、datagen、游戏运行是三个不同阶段。

## 为什么这样设计

- NeoForge 运行测试需要真实启动环境，编译/单测不能覆盖注册、绑定与游戏交互。
- datagen 只验证资源声明与输出，不验证运行时注册成功。
- 手动验收保留测试报告/日志作为证据，避免“曾经编译通过”被当成永久状态。

## 与其他模块的联动

- 注册内核：检查阶段、冻结、插件顺序与启动日志。
- 材料/机器/配方/矿脉/管道：各自的生成、绑定与运行时场景。
- Demo：验证隔离、加载与发布包不夹带 Demo 内容。
- 集成：JEI/Jade/AE 的分类、面板与转移。

## 扩展规范

- 新功能同时补“如何验证”：命令、样本、预期结果、日志位置。
- 测试文档写明适用版本与前置条件；不要把一次性结果写成永久状态。
- 编译通过只记录为编译通过；运行/游戏验收单独记录。
- 修改调度或冻结点时，更新 [注册管线时序](../kernel/registration-timeline.md) 与回归范围。

## 常见坑与防止

- 把 `compileJava` 当成运行验证：注册/绑定/交互未覆盖。
- 忘记 `runClientData`：资源/语言/配方未生成。
- 只用开发客户端验证：专用服务端可能加载失败。
- 发布包夹带 Demo：检查 jar 内容与命名空间隔离。
- 测试报告缺失：无法判断某次验收对应的版本。
