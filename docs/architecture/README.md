# 架构与总览

面向框架开发者。跨模块的定位、边界、编写规范与阅读入口。

## 职责与边界

- 负责：项目定位、模块地图、设计原则、支撑模块边界、文档与扩展规范。
- 不负责：具体模块的类型、数据流与实现细节；这些放 `docs/<module>/README.md`。
- 本目录是总览与规范入口，不重复模块正文。

## 关键内容

- [项目总览](overview.md)：项目定位、解决什么问题、分层与阅读路径。
- [模块地图](module-map.md)：代码模块、职责、依赖与内部入口。
- [框架设计原则](principles.md)：接口、能力组合与最少知道约束。
- [组合式设计与容器地图](composition-model.md)：跨模块策略、能力、声明、计划及容器的边界与阅读路径。
- [支撑模块](support-modules.md)：客户端、配置、辅助、集成、Mixin 的边界。
- [文档编写规范](documentation-conventions.md)：三端放置、模块 README 结构、单点主题与更新检查。
- [模块扩展规范](module-extension-conventions.md)：新增领域/内容/集成时的步骤、联动与踩坑防护。

## 为什么这样设计

跨模块决策集中在一处，避免同一规则散落在多个模块 README；模块 README 只保留与自身职责相关的依据与坑。

## 与其他模块的联动

所有模块 README 从[模块地图](module-map.md)进入；模块之间的依赖、冻结顺序与公开/内部边界在这里统一描述，具体契约仍由模块 README 与 `docs-content` 承载。

## 扩展规范

- 新增跨模块规则、总览或编写规范放本目录。
- 新增模块实现细节放 `docs/<module>/`，并在模块地图与 `docs/README.md` 加入口。
- 不在总览中复制模块正文；用链接指向单点文档。

## 常见坑与防止

- 在 architecture 写某个模块的实现细节：应移到对应模块目录。
- 模块地图与 `docs/README.md` 入口不一致：两处同时维护。
- 总览重复公开契约：公开用法应留在 `docs-content`。

## 文档

从[模块地图](module-map.md)选择模块；从[文档编写规范](documentation-conventions.md)开始写新文档。
