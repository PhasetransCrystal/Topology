# 模块扩展规范

面向框架开发者。新增领域、内容、能力或集成时，按以下顺序放置代码与文档。

## 新增注册领域

1. 定义领域 API 与 `RegistrationDomain` 工厂。
2. 定义继承 `TopoContribution` 的命名钩子接口。
3. 在领域模块中用 `RegistrationPoint` 绑定接口方法与 API。
4. 用 `RegistrationModule.define` 声明真实步骤依赖与贡献后的冻结动作。
5. 把模块加入 `TopoContentBootstrap` 组合清单；不要在 `TopoPlugin` 里加调度分支。
6. 补 `docs/<module>/README.md`、公开契约（如适用）与 `PROJECT_KNOWLEDGE` 入口。

细节见 [新增注册领域](../kernel/registration-domain-extension.md)。

## 新增内容

- 类型/策略/形态先在 foundation 钩子声明，再在内容钩子引用；不要在内容钩子注册新类型。
- 内容声明保留 Entry、ID 或延迟 Supplier；`build()` 只发布句柄，不是冻结点。
- 游戏对象绑定前不要 `.get()`；运行时绑定放在 `registerRuntime` 或对应的能力查询回调。
- 每个声明类都应在所属钩子内显式 `init()`；静态字段不会因插件表锁定自动初始化。
- 新策略优先通过接口继承表达扩展，不在公共方法加入只供少数分支使用的参数。

## 跨模块联动

- 材料是内容基础：机器、配方、矿脉、装备都依赖材料形态与数据。
- 机器依赖材料提供方块/物品，向配方提供 `RecipeLogic`，向管道提供资源类型。
- 配方依赖材料提供输入/输出，依赖机器执行，向 JEI/AE 提供能力分组。
- 矿脉依赖材料宿主形态，向 JEI 提供显示，向 datagen 提供 feature 桥。
- 管道依赖机器资源类型与 block capability，向客户端/Jade 提供勘测与展示。
- 仓储是通用访问层，多方块工具只是调用方；不要向仓储接口传结构元数据。
- 集成是可选适配层，核心领域不要反向依赖 JEI/Jade/AE。

## 常见坑与防止

| 坑 | 防止 |
|---|---|
| 构造期写领域表 | 只在对应钩子内声明；插件表锁定不等于表已冻结 |
| 编译通过就认为注册成功 | 检查冻结边界、静态初始化时机与启动日志 |
| 用 `build()` 当作冻结点 | 材料写入截止在贡献阶段之后；其他表按钩子冻结 |
| 在 `resolveDependencies` 读状态 | 只做结构校验，状态读取放到加载/运行时 |
| 依赖同阶段其他插件先执行 | 同阶段按字典序只为可复现，不是 API 契约 |
| 能力声明支持标签但未实现匹配 | 能力必须实现匹配、消耗、传输与序列化 |
| 把 Demo 状态写成框架契约 | Demo 状态进 `demo-docs` 或 Obsidian，公开契约只写稳定行为 |
| 用 mixin 解决可扩展问题 | 优先公开 API/能力/事件；mixin 只做定点补丁 |

## 验证

- 先编译，再 datagen，再游戏内验证；三者不是同一件事。
- 测试与游戏验收由开发者手动执行，以报告和日志为准。
- 修改调度、冻结或注册点时，同步更新 [注册管线时序](../kernel/registration-timeline.md) 与相关模块 README。
