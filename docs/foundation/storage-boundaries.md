# 通用仓储访问的已确认边界

面向框架开发者；保留已有来源和适用范围。


- `StorageAccess` 是框架通用仓储访问接口，多方块工具只是调用方之一；不依赖蓝图、Cell、`StructureTool`、机器数据域或结构元数据。存储目标、访问身份和权限由实现或适配层封装。
- 批量取出与接收均输入需求 Map，返回实际满足与剩余需求两个 Map；后续实例直接处理剩余需求，不重复扣减，保留物品组件与数量。业务核算、访问顺序和最终剩余处理由调用方负责，通用接口不默认掉落物品。
- 不要求槽位、全量库存或内容快照；背包、绑定箱子、AE 网络、精妙存储背包等由各自实现处理高效访问，不按 Cell／备选反复读仓储。AE 等具体适配暂不处理。
- 通用设计不能仅将多方块的取料／返还接口改名后移出目录；应独立定义仓储访问的资源、请求、操作与结果语义。当前处于文档设计阶段，禁止修改代码；方案中的新接口形态仍待审阅，不能当成已确认 API 或既有实现。

来源：用户于 2026-11-08 的直接要求。适用于通用仓储能力设计，尚未实现；唯一接口契约见 [StorageAccess 仓储访问设计](design-index.md)，多方块接入流程见 [多方块检测与结构工具设计](../machine/design-index.md)。
