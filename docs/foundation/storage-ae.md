# AE 通用仓储访问边界

面向框架开发者。记录 AE 适配的资源和存取边界。

## 资源模型

AE 的仓储以 `AEKey` 表达资源身份，不能将公共访问能力拆成物品仓储和流体仓储。一个 `StorageAccess` 实例接收同一批次的混合 `Resource` 需求，数量使用 `long`，单位分别由对应资源类型定义。

`AeKeyResourceAdapter` 保留物品、流体的数据组件，并允许注册扩展资源与 AE 键之间的映射。`AeResource` 可以直接携带其他 AE 键类型；未知类型不能被当作物品或流体丢弃。多个资源表示可能映射到同一个 AE 键，执行时须共享该键的实际库存，不能分别模拟后将模拟数量相加。

## 定向访问

按本次需求映射出的键访问网络，不先读取或复制整个网络库存。网络可能包含海量种类与数量，完整枚举不能成为定向提取或存入的前置条件。权限、供电、在线状态和真实转移数量以执行时的网络结果为准，模拟结果不是库存预留。

容器内容物与原生网络资源是不同的供给路径。例如水需求既可能由流体键满足，也可能通过物品容器能力满足。后者需要同时管理容器提取、内容物转移和剩余容器返还，不能仅将水桶键改写成水键。候选容器的发现必须有明确的索引或查询能力，不能暗中为每个需求扫描整个 AE 网络。

## 批量存取

`AeStorageAccess` 按请求顺序逐键执行实际存取，返回实际满足量与剩余需求；组合访问将剩余部分交给下一个仓储。跨仓储操作不承诺原子回滚。

AE 的 `Actionable.MODULATE` 本身不参加 NeoForge 事务。当前 `AeStockingResourceHandler` 使用提取日志，在回滚时返还网络；网络拒收的资源进入待返还队列。这是已配置输入窗口的实现，不能直接当作通用仓储接口，也不能据此宣称网络内容可以即时完全恢复。

通用 AE 访问通过 `AeNetworkAccessor` 使用 `StorageHelper`，不采用暂存和重试。`MODULATE` 直接改变网络；其 `SIMULATE` 不预留资源。若中途抛出异常，异常携带此前已确认的转移，当前失败项状态可能未知，不能自动重试。

AE 网络中容器作为流体来源的候选查找尚未实现；原生物品栏的容器能力处理不代表 AE 已支持这一转换。
