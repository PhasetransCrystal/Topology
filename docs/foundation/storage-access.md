# 从仓储访问定义能力

面向框架开发者。此设计尚未实现；除用户明确的边界外，接口形态仍待审阅。


`StorageAccess` 表示资源存取的访问能力，归属框架通用资源访问层；实现可以连接真实仓储，也可以封装虚拟供应策略。
调用方提交“哪些资源、各需要多少”，实现负责在本次权限与连接条件下处理，返回已满足与剩余需求。可选试算通过扩展接口表达。
通用模型不出现施工、材料、返还、蓝图、机器数据域或玩家背包顺序；这些含义由业务调用方赋予。

| 层次 | 职责 | 对外边界 |
|---|---|---|
| 资源模型 | 表示资源身份与数量单位 | 不绑定物品堆叠、槽位或某种仓储 |
| `StorageAccess` | 按批执行资源取出、存入；试算由扩展接口提供 | 不决定业务用途或访问其他仓储的顺序 |
| 仓储适配实现 | 访问身份、权限、目标定位、失效检查、后端 API 与数量转换 | 不要求业务调用方识别箱子、背包或网络类型 |
| 组合访问实现 | 将多个访问实例组成一个同契约实例，处理顺序和结果聚合 | 不自行添加掉落、创造免消耗等业务规则 |
| 业务调用方 | 产生需求，管理实际取出资源和最终剩余资源 | 不操作适配实现的内部槽位或扫描全量库存 |

多方块工具取用和存回物品只是一个使用场景。机器供料可以批量取出物品，流体运输可以存取流体；这些调用不需要多方块控制器或结构元数据。
