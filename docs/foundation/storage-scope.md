# 范围与验收

面向框架开发者。此设计尚未实现；除用户明确的边界外，接口形态仍待审阅。


本轮只定设计，不实现后端或修改代码。具体 mod 的仓储适配、完整库存浏览、跨后端事务、持久化资源预留和全部现有资源系统迁移不在本轮范围内。
通用结果失败类型、适配发现／创建入口，以及现有长数量工具的复用位置仍需实现前核定。

后续实现至少验证：

- 物品与流体使用同一泛型协议，身份组件与基本单位正确，数量超过 `int` 仍可部分转移且不会溢出。
- 无多方块或机器依赖的调用方可直接试算、取出和存入；只读包装、组合实例可互相替换使用。
- 试算不改变存储，整批共享容量不会重复承诺；执行不依赖之前试算结果，库存变化后仍按实际结果核算。
- 不暴露全量库存的模拟大型仓储只收到请求键；有限容器不按每个请求键反复扫描。
- 组合按剩余需求推进，不重复扣减；相同底层存储的多个入口不能被重复试算计数。
- 缺货、容量不足、拒绝访问、目标失效、部分后端失败和不确定结果均有明确处理，不发生静默丢弃或自动重复转移。
- 多方块之外的转运调用能保留目的仓储未接收的资源；不会被通用层强制变成世界掉落物。
