# 仓储适配与复杂环境

面向框架开发者。此设计尚未实现；除用户明确的边界外，接口形态仍待审阅。


访问实例绑定具体目标和访问权限，而不是在每次调用时接受某个多方块上下文。
适配方可以绑定玩家、方块位置与访问面、外部网络身份或可穿戴容器；对目标的有效引用和重新解析由适配方管理。
创建访问实例不代表权限和连接永久有效，实际操作时仍须检查，不能继续使用已经失效的缓存句柄。

| 后端示例 | 实现方式与边界 |
|---|---|
| 玩家物品栏／有限箱子 | 可一次遍历处理整个请求；不对每个请求键重新扫描全部槽位 |
| AE 等大型网络 | 按请求键使用网络索引或后端批量 API；不拉取全量物品清单到框架内 |
| 精妙存储背包等外部容器 | 通过对应模组公开能力适配，不要求它伪装成玩家原生物品栏 |
| NeoForge 槽位处理器 | 在适配层复用现有资源类型、事务和长数量转移能力，外层仍处理整批请求 |

现有 `LongResourceHandler` 和 `ResourceHandlerLongOps` 已提供 `long` 数量及受限的 `int` 分段兼容逻辑；应复用其适用能力，不另写不受限的海量循环。
它们当前位于机器包，通用访问层不能因此反向依赖机器业务；实现前须确定复用或迁移边界，本轮不修改这些代码。
通用接口也不把 NeoForge 事务强加给不能参加同一事务的外部仓储。

访问成本以请求批次和实际后端能力组织；限额或执行预算使本批只能部分完成时，保留其余需求，并给出相应原因。
公共接口不要求仓储枚举、槽位数、库存快照或总容量查询。全量浏览／分页搜索是另一个可选能力，不能成为定向存取的必需接口。
