# 组合也提供 StorageAccess

面向框架开发者。此设计尚未实现；除用户明确的边界外，接口形态仍待审阅。


组合器自身实现同一个 `StorageAccess<R>`，允许业务调用方只持有一个访问入口。
其按调用方选择的顺序，将前一个实例返回的 `remaining` 传给下一个，汇总满足量和原因，需求清空时停止。
业务无需自己再写一套背包、箱子和网络的专用分支，也不预设哪种仓储优先。

执行时每次均依据实际结果推进。试算组合则还要考虑多个入口是否访问同一个底层存储，以及共享容量是否被重复计算。
适配／组合层能识别等价访问目标时应合并或去重；不能识别时，不能宣称独立试算的总和一定可共同满足，也不能对该组合提供试算扩展。
只读限制、资源过滤等可通过实现相同接口的包装器组合，不要求扩展方继承某个背包实现或机器组件。

源仓储取出再向目标仓储存入，是由两个访问实例组成的转运流程，超出单个访问操作的原子范围。
目标实际接收不足时，转运方仍持有余量，应按其策略暂存或尝试存回；通用接口不静默丢弃，也不强制生成掉落物。
