# 框架设计基本准则

面向框架开发者；保留已有来源和适用范围。


- 框架封装复杂逻辑并遵守最少知道原则；通用能力不要求调用方了解特定后端或其他能力的内部实现。
- 扩展能力通过接口继承表达，少数分支所需参数归属相应扩展契约，不向所有调用方传播。参数对象应表达一致职责与约束，不能只作为原长参数列表的搬运容器。
- 输入组装处选择实现，框架流程统一调用接口，通过多态与能力组合减少分支；具体环境差异封装在实现中，不让公共流程反复判断玩家模式、调用来源或后端类型。

来源：用户于 2026-11-08 明确提出的框架设计准则；适用于全框架的接口设计与审查。执行约定见 [AGENTS.md](../../AGENTS.md)。
