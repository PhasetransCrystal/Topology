# 批量操作契约

面向框架开发者。此设计尚未实现；除用户明确的边界外，接口形态仍待审阅。


以下为接口形态建议，除 `StorageAccess` 外的辅助命名仍可调整；这里只描述文档，不添加 Java 文件：

```java
interface StorageAccess<R extends Resource> {
    StorageResult<R> extract(Map<R, Long> request);
    StorageResult<R> insert(Map<R, Long> request);
}

interface SimulatableStorageAccess<R extends Resource> extends StorageAccess<R> {
    StorageEstimate<R> simulateExtract(Map<R, Long> request);
    StorageEstimate<R> simulateInsert(Map<R, Long> request);
}

record StorageResult<R extends Resource>(
    Map<R, Long> fulfilled,
    Map<R, Long> remaining,
    List<StorageIssue<R>> issues
) {}
```

两种方向共享相同输入输出，允许部分满足，不默认要求整批全成。只读或仅输入的访问实例也可使用同一接口；被禁止的方向返回未满足需求及原因。
不强制“先试算、再执行”两次访问，调用方可以直接执行整批操作。
`StorageEstimate` 使用同样的已满足、剩余与原因数据形态，但表示估算，不可当作实际转移凭据。
需要试算的入口依赖 `SimulatableStorageAccess`，普通存取入口只依赖 `StorageAccess`。能力适配与组合由框架集中封装，不在每次存取中传模式参数或判断具体仓储类型。

### 试算与执行必须区分

| 入口 | `fulfilled` 的含义 | 是否改变资源归属 |
|---|---|---|
| 扩展接口的 `simulateExtract`／`simulateInsert` | 在本次观测条件下，整批请求能够满足的部分 | 不改变仓储内容，不交付资源 |
| 基础接口的 `extract`／`insert` | 本次实际取出或实际存入的部分 | 按实际结果发生转移 |

试算必须按整批考虑共享容量、槽位过滤和其他共享限制，不能独立试算每个键再简单相加。
例如同一个空槽只能装下一组资源时，不能同时向两种物品都报告可以占满该槽。
请求按本次输入 Map 的迭代顺序确定共享空间的分配优先级，适配和组合过程须保留这一顺序；需要稳定优先级的调用方应提交有序 Map。
试算与执行均遵循该顺序，但两次调用之间库存或权限可能变化，因此试算不是预留，也不是后续执行的数量承诺。

适配实现没有可靠试算能力时，只提供基础存取接口，不声明试算扩展；不能通过真实取出再放回伪造无副作用查询。
这不影响其实现实际存取；部分后端所需的事务内暂存与回滚，由能保证该语义的适配实现自行处理。

### 结果守恒与资源归属

- 对每个请求键，`request = fulfilled + remaining`；不得返回请求之外的资源、超过请求的数量或不同组件的替代资源。
- 实现不修改输入 Map；结果与原因数据在返回后保持不可变。后续访问直接使用 `remaining`，不再重复扣减。
- 执行取出后，`fulfilled` 对应的资源由调用方管理；真实仓储相应扣减，虚拟提供器按自身供应策略满足。调用方负责消耗、暂存或再次存入，结果中的数量是本次取得资源的凭据，不是库存视图。
- 执行存入前，调用方必须持有相应资源；返回后按 `fulfilled` 核销，继续持有 `remaining`，不得重复提交已经存入的部分。
- 试算结果不构成资源凭据，不能用于实际消耗或核销。接口也不承诺资源预留、重复调用幂等或跨存储原子事务。

### 原因与部分失败

`StorageIssue<R>` 的建议内容为命名空间原因码、受影响的请求键（或整个请求）、参数数据。仓储层不直接输出聊天或决定重试／掉落。
库存不足、容量不足、方向不允许、无权限、目标失效、未加载、断开连接和后端故障应能区分，不能统一当作“材料不足”。
`remaining` 表示未发生转移的需求，原因用于解释为何未完成，不重复记作另一份物品。

批量处理中途失败时，普通返回仍须包含此前已经确认的实际转移和确定未转移的部分，并保持数量守恒。
若后端无法确认某次调用是否已转移，不能将该部分谎报为未转移并自动重试，也不能伪造满足量。
这类不确定结果须通过携带已确认转移与不确定请求范围的失败通道上报，停止该批自动续传或补偿；具体异常／失败类型在实现前定稿。
不能承诺用一次“存回”必然回滚，因为目标可能已满、失效或拒绝访问。
