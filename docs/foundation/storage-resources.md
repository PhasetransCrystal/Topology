# 资源身份与数量

面向框架开发者。此设计尚未实现；除用户明确的边界外，接口形态仍待审阅。


接口使用资源类型参数 `R`，以 `Map<R, Long>` 表达整批需求。每个访问实例服务一种资源类型，不把不同计量单位混进同一个 Map。
优先沿用项目已有的 NeoForge `Resource` 表示：物品使用 `ItemResource`，流体使用 `FluidResource`。不再新造仅服务结构工具的 `ItemKey`。
这不是注册为机器资源类型的前提；公共接口不依赖 `MachineResourceType` 或机器数据系统。

- 键表示稳定的资源身份，包含该资源所需的组件等区分信息，不能使用可变 `ItemStack`／流体堆栈作键。
- 数量使用非负 `long`，遵守对应资源的基本单位；不能使用物品最大堆叠数或后端的 `int` 限制作为公共数量上限。
- 空资源、负数、空键应在发生存储变更前拒绝；零数量可规范化省略。合并数量必须检查溢出。
- Tag、可互换候选、同型／等级约束属于需求解析。调用方先确定确切资源，不让仓储接口隐式替换资源。

其他资源可在满足相同身份和计量契约后适配，不在本轮承诺全部资源类型的具体实现。
