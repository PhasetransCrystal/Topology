# 配置模块内部

面向框架开发者。配置模块只定义 NeoForge 配置项与配置语言键，不注册内容领域。

## 职责与边界

- 负责：配置定义、读取入口、配置语言键。
- 不负责：内容注册、领域表冻结、运行时状态管理。
- 配置值不能替代领域声明；需要注册的内容仍走对应钩子。

## 关键类型与数据流

- `TopoConfiguration`：配置定义与读取。
- `TopoConfigLang`：配置项语言键。
- 数据流：配置加载 → 功能读取 → 语言键导出。

## 为什么这样设计

- 配置集中定义，避免业务代码散落裸键或重复读取。
- 配置语言键走同一语言模块，保证本地化与资源包归属。
- 配置不参与领域注册，避免用配置开关改变已冻结的表。

## 与其他模块的联动

- 运行时/机器/客户端按需读取配置；不在声明期依赖未加载配置。
- 语言模块导出配置键；Jade 等外部键用 `absolute`。
- 配置不能改变注册阶段或冻结边界。

## 扩展规范

- 新配置项在 `TopoConfiguration` 定义，默认值明确，读取点集中。
- 新配置语言键用 `TopoConfigLang`/语言模块，不硬编码。
- 配置开关只影响运行时行为，不用于跳过注册声明。
- 补 `docs-content` 中对应的下游说明（如适用）。

## 常见坑与防止

- 在构造期读取配置并决定注册内容：配置可能尚未加载，且会破坏阶段边界。
- 用配置动态冻结/解冻领域表：冻结是单向的。
- 硬编码配置键：走语言模块与 `absolute` 规则。
- 配置默认值变化未记录：在模块 README/变更说明中标注。
