# StructureTool 的公共能力

面向框架开发者。此文保留原设计中的已确认约束和待落实方案；实现状态以相关章节及源码为准。


以下是能力边界，尚不固化成具体类和方法签名：

| 能力 | 输入 | 输出 |
|---|---|---|
| 检测 | 世界读取上下文、锚点、结构定义、周期元数据组 | 探测后的元数据、实际结构报告及结构化错误 |
| 预览与规划 | 已有元数据、目标配置、Cell 内容声明、当前观测 | 反推的目标布局、待施工位置、材料需求与阻塞原因 |
| 分批补建 | 结构信息、世界访问、权限能力、仓储提供者 | 本批实际变化、材料消耗、剩余需求与错误 |
| 拆除 | 元数据、明确的拆除目标、权限与掉落上下文 | 实际拆除结果、所得物品与错误 |
| 返还 | 元数据、待返还物品、有序提供器、掉落上下文 | 各来源实际接收量及最终掉落物 |

核心可以使用物品资源描述材料，但不能依赖某个工具 Item 作为操作入口。
也不能把手持校验、潜行、玩家背包、聊天输出、菜单有效性或预览清理条件写成工具核心的前提。

Demo Item 继续承担右键检测、普通右键配置、Shift＋右键补建等交互。
一键拆除的具体按键／GUI 入口尚未确定，不在本轮擅自绑定手势。
其他调用方可通过自身 GUI、命令或机器逻辑使用相同能力。

### 放置入口的四类必要输入

放置入口按用户确认的四类信息收敛，具体类型与方法签名仍待设计：

| 输入 | 表达的信息或能力 |
|---|---|
| 结构信息 | 蓝图与本次结构元数据，以及已确定的锚点、朝向、整体镜像和重复次数等施工要求；由框架内部解析与规划，避免调用方另行拼接不一致的计划、蓝图和可变配置 |
| 世界信息 | 本次操作所属世界及读取、写入、环境复核、更新和恢复所需的访问能力；读取与写入必须指向同一世界，只读 `StructureView` 本身不承担世界修改 |
| 玩家权限信息 | 本次操作的建造与位置访问等权限；通过权限能力提供，玩家特有校验由相应实现封装；免材料由传入的仓储实现表达 |
| 仓储提供者 | 通用 `StorageAccess` 访问入口，内部可组合多个仓储；工具仅提交整批请求并处理实际满足与剩余需求 |

框架封装目标解析、批次选择、写入前复核、事件处理、世界修改、结构校验、材料结算与本批失败恢复。
调用方提供这四类输入即可，不需要了解槽位分配、候选编译、快照管理或内部执行顺序。
`ServerPlayer`、工具物品、点击面等特定调用分支需要的信息，由对应权限／交互扩展接口及其实现承载，不继续作为公共放置入口的独立参数。
扩展信息在框架相应能力内使用，不要求通用执行流程读取玩家或物品细节；也不能将原有参数原样装入一个公共 Context 作为替代。

输入组装时完成差异化能力选择：普通玩家使用真实仓储访问，创造玩家使用无条件满足取出需求的虚拟提供器。
放置核心统一调用 `StorageAccess` 并依据返回结果执行，不再判断创造模式、免材料权限或提供器的具体类型。
建造权限、位置访问与世界约束仍通过各自契约检查。用于接收余料和拆除所得的策略独立配置，不从虚拟取料推导接收行为。
