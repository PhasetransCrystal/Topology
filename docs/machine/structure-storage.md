# 通用仓储访问的多方块接入

面向框架开发者。此文保留原设计中的已确认约束和待落实方案；实现状态以相关章节及源码为准。


`StorageAccess` 是框架通用仓储访问接口，多方块工具仅是调用方之一。
批量请求、实际满足与剩余需求、仓储适配和访问效率的唯一契约见 [StorageAccess 仓储访问设计](../foundation/design-index.md)，本节仅描述多方块侧的组合流程，尚未实现。

工具读取结构元数据并规划确切物品需求，随后向调用方提供的 `StorageAccess<ItemResource>` 提交整批 Map 调用实际存取方法。多个存储可先组合成同契约的访问实例。
公共仓储接口不接收结构元数据，也不承担结构判断或世界修改。工具侧保留施工核算、返还记录与掉落上下文。

### 顺序取料

```text
完整的剩余需求 Map
  → StorageAccess A 实际取料，返回 fulfilled 与 remaining
  → 汇总 fulfilled，将 remaining 直接传给 StorageAccess B
  → StorageAccess B 返回本次 fulfilled 与 remaining
  → 需求清空或提供器耗尽
```

例如需求为 `{铁:64, 铜:32}`，背包提供 `{铁:20, 铜:10}`，后续仓储只收到 `{铁:44, 铜:22}`。
这里的 A、B 只是调用方指定的顺序，不预设背包优先，也不要求调用方是玩家。
存储不可访问时不能视为已经满足；确定未实际转移的需求留在 `remaining`，并保留仓储侧的原因，供后续实现处理。不确定是否转移的故障按通用失败契约停止自动续传，不能假定全部未转移。

每批记录各提供器实际取出的材料，用于执行核算、未用材料返还和失败恢复。
库存变化以实际转移结果为准，不把先前查询或模拟结果当成取料承诺。

### 顺序返还与最终掉落

```text
待返还物品 Map
  → StorageAccess A 实际接收，返回 fulfilled 与 remaining
  → 将 remaining 直接传给 StorageAccess B
  → 所有提供器处理后仍有剩余
  → 在指定世界位置生成掉落物
```

返还不要求只能返回原提供器；施工余料、失败回滚和一键拆除所得物品共享这条流程。
任何未接收部分都不能静默丢弃，最终剩余必须转换成保留物品组件的真实掉落物。
世界和掉落位置由执行上下文提供，不要求调用方是玩家或 Item。

背包仅是计划提供的一种实现，其他 mod 通过实现 `StorageAccess` 接入仓储。AE 等具体适配不在当前实现范围内。
创造模式免材料通过调用前注入的虚拟提供器实现；取料流程统一处理结果。接收余料和拆除所得仍遵守显式配置的存入策略。
